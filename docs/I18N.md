## Feature ownership

Paraglide is part of every application, including single-language deployments.
Non-removable application-shell messages live under `src/app/messages`, while
removable messages stay with their feature. Both are split by concern:

```text
src/app/messages/en/common/header.yaml
src/feat/auth/login/messages/en/page.yaml
src/feat/blog/posts/messages/en/list.yaml
src/feat/blog/posts/admin/messages/en/list.yaml
src/feat/blog/posts/profile/messages/en/section.yaml
```

The path after the locale produces an app namespace such as `common.header`.
The full feature path produces `auth.login.page`; its body contains `title`, not
`auth.login.page.title`. App and feature namespaces may not overlap. Deleting a
feature therefore deletes its source messages without editing a central
catalog, while shell copy remains available.

## Two-document YAML

Each file has exactly two YAML documents. Build-only metadata comes first and
namespace-local messages second:

```yaml
---
description: Public post list copy with executable ICU examples.
generated: true
examples:
  resultCount:
    values: { count: 3 }
    expected: 3 posts
---
title: Journal
resultCount: "{count, plural, =0 {No posts} one {# post} other {# posts}}"
```

The metadata schema is strict. `description` and `generated: true` are required;
`examples` is optional. Metadata documents why generated copy exists and make
non-trivial messages executable, but never ship in runtime JSON.

## ICU examples

ICU MessageFormat handles interpolation, selection/gender, pluralization,
ordinals, and localized number/date/time output:

```yaml
examples:
  greeting:
    values: { gender: female, name: Ada }
    expected: Welcome back, Ada.
---
greeting: "{gender, select, female {Welcome back, {name}.} male {Welcome back, {name}.} other {Welcome, {name}.}}"
```

Generation compiles every message even when it has no example, executes every
example with its locale, and compares exact output. It also requires every
locale to expose the same flattened keys.

## Generation pipeline

```text
app and feature YAML
  -> Bun.Glob discovery and two-document parsing
  -> validated, flattened messages/<locale>.json
  -> Paraglide ICU plugin
  -> typed src/app/paraglide modules
```

`bun run features:sync` owns the first generated output;
`bun run i18n:compile` owns Paraglide output; `bun run generate` performs both
and regenerates the route tree. Generated JSON and modules are gitignored and
stale locale files are removed atomically.

`project.inlang/settings.json` is the authored Paraglide/Inlang configuration.
The unpacked project's own `.gitignore` keeps its generated cache, SDK metadata,
README, and ignore file out of commits, while `.prettierignore` keeps those
generator outputs byte-stable. Do not replace the nested ignore with a broad
root rule that would also hide `settings.json`.

The development watcher uses `node:fs/promises` events for both source roots,
while `npm-run-all` runs it beside Vite. A generation failure leaves the last
complete output in place and reports the invalid file.

## Consuming messages

Paraglide exposes each dotted catalog ID as a string-named module export.
Import the exact ID statically and give it a readable local alias:

```tsx
import {
  "blog.posts.list.resultCount" as blogPostsListResultCount,
  "blog.posts.list.title" as blogPostsListTitle,
} from "~/app/paraglide/messages.js";

<Heading>{blogPostsListTitle()}</Heading>;
<Text>{blogPostsListResultCount({ count: posts.length })}</Text>;
```

Avoid `import * as m` followed by `m["blog.posts.list.title"]()`. Static named
imports keep each dependency visible to the bundler, preserve tree shaking, and
avoid Biome's dynamic namespace-access diagnostic. The local alias only needs
to be unique within its source module; the dotted catalog ID remains the stable
cross-locale key.

## Adding copy

1. Choose the smallest feature/page/component path that owns the copy.
2. Add matching two-document YAML files for every configured locale.
3. Keep keys relative to the path namespace.
4. Add exact examples for select/plural/interpolated messages.
5. Run `bun run features:sync`, then `bun run i18n:compile`.

The [Paraglide documentation](https://inlang.com/m/gerre34r/library-inlang-paraglideJs)
and [ICU MessageFormat](https://unicode-org.github.io/icu/userguide/format_parse/messages/)
are the syntax authorities.
