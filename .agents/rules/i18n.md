## Ownership

- Every application has Paraglide internationalization even when it initially exposes one locale.
- Keep non-removable application-shell copy at `src/app/messages/<locale>/**/*.yaml`; its namespace is the path after the locale, so `en/common/header.yaml` becomes `common.header`.
- Keep messages with the feature that owns the copy at `<feature>/**/messages/<locale>/**/*.yaml`.
- Namespace comes from the path. `auth/login/messages/en/page.yaml` becomes `auth.login.page`; the file contains only keys below that namespace.
- App and feature namespaces must not overlap; generation fails instead of allowing either owner to overwrite the other.
- Keep catalogs split by page/component concern. Never rebuild a monolithic routes file.

## File contract

- Each YAML file contains exactly two documents.
- The first document is strict build-only metadata: non-empty `description`, `generated: true`, and optional executable `examples`.
- The second document contains only namespace-local ICU message strings. Do not repeat the path namespace.
- Metadata never enters browser/runtime catalogs.

## ICU examples

- Use ICU MessageFormat for interpolation, `select`/gender, plurals, ordinals, numbers, dates, and time.
- Give non-trivial messages a front-matter example with primitive `values` and exact `expected` output.
- The generator compiles every message and executes every declared example. A stale example or invalid ICU expression must fail generation.

## Generation

- `bun run features:sync` uses `Bun.Glob` to merge app- and feature-owned sources into deterministic, parity-checked `messages/<locale>.json` files and removes stale locale output.
- `bun run i18n:compile` compiles those files to typed, ignored `src/app/paraglide/**` modules.
- `bun run generate` performs both steps and regenerates routes. The development watcher uses `node:fs/promises` and rebuilds after feature changes.
- The development watcher rebuilds after either a feature source or app-message source changes.
- `project.inlang/settings.json` is the only authored file in the unpacked Inlang project. Its directory-owned ignore file excludes generated cache, SDK metadata, and README output from Git, and Prettier excludes those outputs too.
- Statically import each dotted message export with a local alias, for example `import { "common.home.title" as commonHomeTitle } from "~/app/paraglide/messages.js"`. Do not use a namespace import plus bracket access; direct imports preserve tree shaking and satisfy Biome's static-access rule.
- Never edit generated JSON or Paraglide modules directly.
